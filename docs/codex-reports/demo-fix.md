# demo-fix 交付与实局验收记录

> 状态：**PR 候选，严格验收未通过**。功能修复和真实浏览器回归已完成，但 Zerone Runtime 在两轮快速回归中分别出现 120 秒无结果和 HTTP 502，未满足“连续两局均无需人工恢复”的硬性标准。本报告只记录实际观察结果，不以单元测试代替实局。分支 `codex/demo-fix` 基于 `d27765246457b074a9e346d5e16c48d86c27865c`。PR 链接及最后提交哈希在推送后填写。

## 从零启动

```bash
cd zerone-wolfcha
pnpm install --frozen-lockfile
cp .env.example .env.local
# 在 .env.local 配好九名 Zerone Agent 的 ZERONE_AGENTS_JSON、百炼语音 Key，保留 ZERONE_CROSS_GAME_MEMORY=0
# 正式验收保持 NEXT_PUBLIC_ZERONE_QUICK_PLAYER_COUNT=10；仅节省 Token 的快速回归可设为 8
pnpm dev
# 浏览器打开 http://127.0.0.1:3000/zh
```

`dev` 与 `start` 仅绑定 `127.0.0.1`。密钥仅填本机 `.env.local`，不提交。

为提高演示和回归效率，另做了四项不改变狼人杀规则的演示能力：

- `DialogArea.tsx`、`useGameLogic.ts`：真人语音识别成功后，在演示模式自动提交为公开发言并结束本人的发言回合，无需再点“发送/结束发言”。
- `useGameLogic.ts`、`api/zerone/sessions/route.ts`：增加 `NEXT_PUBLIC_ZERONE_QUICK_PLAYER_COUNT`，允许以 8 人快速回归；正式验收默认仍为 10 人、9 个 Agent，真人固定 3 号。
- `useDayPhase.ts`：演示模式下 AI 台词可自动连续推进；需要人工观察时仍可用 Enter 跳过当前语音。
- `ai-activity.ts`：新开一局时清空上一局活动记录，避免两局证据混在一起。

`src/lib/demo-fix-metrics.ts` 在浏览器 `sessionStorage` 按 gameId 记录预取命中、自动重试及失败计数。可用 `wolfcha_demo_fix_metrics_<gameId>` 导出。

## 录屏与已知问题

- **3–5 分钟录屏未交付。** 不能用截图拼接冒充录屏；正式提交验收前仍需录制并保留“Agent 思考中”等待画面。
- 真实 Agent 的响应尾延迟仍显著：观察到 HTTP 502、单次发言连续 120 秒无可用结果。前端会暂停并允许重试，不会伪造台词，但目前无法保证完全不需要人工恢复。
- 两轮为用户要求的 8 人节省 Token 快速回归，不等价于原验收要求的 10 人（9 个 AI Agent）连续两局。正式验收必须把 `NEXT_PUBLIC_ZERONE_QUICK_PLAYER_COUNT` 恢复为 `10`。
- 服务退出日志还观察到一次阿里云语音请求超时；语音自动提交已通过，但 AI 朗读的服务稳定性仍依赖外部语音服务。
- 当前未修改狼人杀规则、阶段提示词或输出解析，未接入备用模型、实时语音、私聊或 Hub 座位服务。
